# Day 1 Guarded Apriori Mining Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Mine interpretable next-session rules on a declared chronological training subset, with explicit leakage guards and correct daily denominators.

**Architecture:** src/mining.py consumes complete dated samples from src/labels.py, selects only mature outcomes, optionally limits the fitting history, then encodes one transaction per feature session. mlxtend Apriori produces itemsets up to length three; association_rules and role/lift filters retain only one/two feature antecedents and a single next-session stock consequent. The CLI is offline and optional artifacts preserve training provenance.

**Tech Stack:** Existing Python 3.13/pandas/numpy/pytest plus mlxtend. Install without relaxing existing pinned dependencies; freeze the exact resolved environment.

- Create src/mining.py: MiningResult, build_transactions, mine_rules, select_rules, CLI and private serialization.
- Create tests/test_mining.py: actual Apriori on small synthetic transactions, cutoff/role guards, arithmetic and artifact checks.

build_transactions(samples, stocks, cutoff, window=None) returns a boolean item table and a dated session table. mine_rules uses that boundary and returns a MiningResult with rules, transactions, sessions, cutoff and original thresholds. select_rules allows only stricter support/confidence filtering of that result; lower thresholds require re-mining.
