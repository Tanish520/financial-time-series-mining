# Day 1 Labels and Availability Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Produce causal U/D/N stock features and next-session intraday targets, with explicit outcome availability and a tested future-data boundary.

**Architecture:** src/labels.py consumes the validated, frozen data from src/data.py. It returns separate feature, target and complete supervised-sample tables; a date-based helper selects only outcomes known by a session-close cutoff. An offline CLI previews counts and optionally writes versioned derived CSVs with source lineage.

**Tech Stack:** Existing Python 3.13, pandas, numpy and pytest; no new dependency and no market-data request.

---

## Files and interfaces

- Create src/labels.py: LabelTables, label_returns, build_label_tables, eligible_training_samples, CLI and private serialization helper.
- Create tests/test_labels.py: synthetic prices with two stocks plus the benchmark; date/return assertions, future-data mutation, prefix invariance and artifact checks.
- Modify README.md: actual counts, a runnable offline check and an observed feature/target example.
- Leave the accepted data/raw/day1_three_stocks snapshot and src/data.py unchanged.

LabelTables contains features, targets and samples DataFrames. Features have feature_session, feature_available_session, ticker, feature_return, feature_label and feature_item. Targets have feature_session, ticker, execution_session, outcome_available_session, target_return, target_label and target_item. Samples join those tables and retain only rows with both a known feature and known target. Availability dates mean after that session's close, not midnight observations.

The benchmark supplies the validated calendar and stays out of mined stock features and targets. Items strip the .NS suffix: AAA_U and NEXT_AAA_D. Missing initial feature returns and missing final targets remain unavailable, with no N substitution.

## Task 2: Implement labels and availability

- [x] Validate theta as a finite decimal return strictly between zero and one. U means above theta; D means below -theta; equality means N. Use an explicitly recorded absolute tolerance of eight float64 machine epsilons solely to avoid mislabelling mathematically equal boundaries due to division round-off.
- [x] Preserve missing returns as nullable missing labels/items and reject infinite returns. Test ordinary values just outside either boundary so the tolerance cannot become a materially wider threshold.
- [x] Validate source prices with the existing data contract, sort within stock, then compute feature returns from close / previous_close - 1 with no filling.
- [x] Compute target returns from next_close / next_open - 1. Shift observed session dates with the target prices; never add a calendar day or guess a future exchange date.
- [x] Build features and targets separately. Keep unknown initial/final rows for audit; make samples contain only complete pairs.
- [x] Implement eligible_training_samples(samples, cutoff) using outcome_available_session <= cutoff and explicit date-only session-close semantics. Reject intraday or timezone-aware cutoffs that could be misinterpreted as close cutoffs.
