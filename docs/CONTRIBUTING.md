# Working with the project

Tanish owns the temporal pipeline and accounting; Aayush can maintain presentation, the report and demo. Both should inspect a fold and ledger before interpreting results. These are suggested human responsibilities, not a claim about work already performed.

## Main commands

```bash
make test
make app
make reproduce RUN_DIR=data/results/new_experiment
make report
```

Use Python 3.13 and the pinned requirements. Mining and matching are deterministic; no stochastic model is used. Tests that shuffle rows use explicit seeds. Reproduction reads the frozen corrected snapshot, never a live download.

## Research changes

Freeze the grid and protocol before a new held-out experiment. Never change settings because the existing test curve looks poor. Record any exploratory change and reserve a new untouched evaluation period. Keep the original artifacts and choose a new output directory.

Features become available after their named session closes. A next-session target becomes eligible only after its own execution closes. Preserve the common validation dates, 1/N current-equity allocation and continuous capital across folds. Unknown predictions are not neutral predictions.

## Display changes

The app reads a versioned checksum-protected bundle. A filter changes presentation only. Do not import the research engine into core pages, retrain from a button or combine cached and partially fetched predictor cohorts. Keep the Latest refresh boundary separate and explicit.

## Reports

The report builder reads the verified saved bundle. Regenerate after an explicitly versioned experiment, then render the PDF and inspect every page. Never type a different return into a report to match an expected story. Keep the 0.5% scenario's convention explicit and avoid claiming an unverified direct replication of an earlier study.

Scope remains daily equities, Apriori and the five-view app. Deep learning, fuzzy sets, SAX, clustering, text mining, databases and logins are outside this implementation.
